PC sin Internet: diagnóstico desde cable hasta DNS

Introducción

Objetivo

Flujo para diferenciar enlace, DHCP, gateway, Internet y DNS. La guía busca que puedas separar causas antes de sustituir componentes.

Antes de empezar: seguridad

⚠ Precaución

Desconecta el equipo cuando corresponda y no realices mediciones peligrosas sin formación e instrumental. En baterías, fuentes y placas, detén el procedimiento si detectas daño físico, líquido, olor extraño o calor anormal.

  • Documenta el estado inicial.
  • Haz una sola modificación cada vez.
  • Conserva tornillos, cables y configuración original.

Herramientas

CMD/PowerShellCable EthernetWi‑FiPingipconfig
01

1. Enlace

Sin enlace no hay que tocar DNS.

Qué hacer

  1. Revisa el ícono de red: una X o triángulo de advertencia indica sin enlace o adaptador deshabilitado; un globo terráqueo indica enlace sin Internet.
  2. Si es cable, verifica las luces del puerto en la tarjeta y en el router: ausencia total de luz en cualquiera de los dos extremos apunta a cable, puerto o adaptador dañado.
  3. Si es Wi-Fi, confirma que el adaptador esté habilitado y que veas la red esperada en la lista.
  4. Prueba con otro cable o puerto del router para descartar esa variable.
Punto de control

Sin enlace no hay que tocar DNS ni configuración de IP: si no hay conexión física/inalámbrica establecida, cualquier configuración de red es irrelevante hasta resolver esto primero.

Interpretación

Sin enlace no hay que tocar DNS.

02

2. IP

Comprueba si el equipo recibió una dirección válida.

Qué hacer

  1. Revisa con ipconfig /all la IP, máscara y gateway asignados.
  2. Si la IP empieza con 169.254.x.x (APIPA), el equipo nunca logró contactar al servidor DHCP.
  3. Renueva con ipconfig /release seguido de ipconfig /renew como administrador.
  4. Compara con otro equipo que funcione en la misma red (misma máscara y rango de gateway).
Punto de control

Comprueba si el equipo recibió una dirección válida antes de seguir: sin IP correcta en el rango del gateway, ninguna prueba posterior tendrá sentido.

Interpretación

Comprueba si el equipo recibió una dirección válida.

03

3. Gateway

El gateway prueba conectividad con la LAN.

Qué hacer

  1. Ejecuta ping a la dirección del gateway obtenida en el paso 2.
  2. Si falla con IP correcta, revisa si estás en la VLAN o red Wi-Fi correcta (fácil de confundir con redes de invitados).
  3. Revisa el firewall de Windows por si bloquea el ICMP saliente.
  4. No cambies DNS todavía: este fallo es de capa de red local, el DNS no interviene aquí.
Punto de control

El gateway prueba conectividad con la LAN: si no puedes hacer ping al router desde tu propia red, el problema es previo a cualquier intento de salir a Internet.

Interpretación

El gateway prueba conectividad con la LAN.

04

4. IP pública y DNS

Separa Internet de resolución de nombres.

Qué hacer

  1. Ejecuta ping 1.1.1.1 para probar salida a Internet sin depender de DNS.
  2. Si funciona, prueba ping google.com o abre un navegador para probar resolución de nombres.
  3. Si la IP responde pero el dominio no, cambia temporalmente el DNS del adaptador a 1.1.1.1 u 8.8.8.8 en las propiedades de IPv4.
Punto de control

Separa Internet de resolución de nombres: confundir un problema de DNS con uno de conectividad general hace revisar router y cables cuando el único problema era el servidor DNS.

Interpretación

Separa Internet de resolución de nombres.

Diagnóstico final

Resultado: si todas las pruebas externas son correctas y el fallo permanece, ya tienes una hipótesis más concreta. No cambies chips, puertos o placas por intuición: documenta síntomas y mediciones.

Fuentes y notas

El flujo de diagnóstico es deliberadamente por capas para evitar cambios innecesarios.
