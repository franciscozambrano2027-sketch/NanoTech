Cómo usar los comandos: primero ejecuta las consultas de diagnóstico; después aplica la configuración; finalmente vuelve a consultar para confirmar el cambio. Los valores de ejemplo deben adaptarse a tu interfaz WAN/LAN y subred.

Introducción

Objetivo

Ejemplo RouterOS v7 para una LAN 192.168.88.0/24, con gateway 192.168.88.1 y pool de clientes. La guía busca que puedas separar causas antes de sustituir componentes.

Antes de empezar: seguridad

⚠ Precaución

Desconecta el equipo cuando corresponda y no realices mediciones peligrosas sin formación e instrumental. En baterías, fuentes y placas, detén el procedimiento si detectas daño físico, líquido, olor extraño o calor anormal.

  • Documenta el estado inicial.
  • Haz una sola modificación cada vez.
  • Conserva tornillos, cables y configuración original.

01

1. Hacer respaldo

Antes de configurar, guarda export y backup.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Respaldo antes del cambio · COMANDO PRINCIPAL Copiar
/export terse file=nucleo-tech-dhcp-before
/system backup save name=nucleo-tech-dhcp-before
CONSULTA · VERIFICACIÓN
/file print detail

Exporta toda la configuracion actual a un archivo de texto (.rsc) legible, que puedes descargar o leer en pantalla. Es tu respaldo "en texto plano" antes de tocar nada: si algo sale mal, sabes exactamente que habia antes. Lista los archivos guardados en el router -respaldos, exports, logs-. Usalo para confirmar que el archivo se creo, revisar su tamano y su fecha.

02

2. Crear IP de la LAN

El gateway debe tener una IP en la interfaz LAN/bridge.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Configurar gateway LAN · COMANDO PRINCIPAL
/ip address add address=192.168.88.1/24 interface=bridge1 comment="LAN gateway"
CONSULTA · VERIFICACIÓN
/ip address print detail

Asigna una direccion IP a una interfaz del router (aqui, la propia IP del router dentro de la LAN). Sin este paso el router no tiene una "puerta" en esa red y no puede repartir direcciones ni enrutar trafico. Lista las direcciones IP asignadas a cada interfaz. Confirma que la IP se creo correctamente y que no choca con otra direccion ya existente en la red.

03

3. Crear pool

El pool define las direcciones que DHCP entregará.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Crear pool de clientes · COMANDO PRINCIPAL
/ip pool add name=dhcp_pool0 ranges=192.168.88.10-192.168.88.254
CONSULTA · VERIFICACIÓN
/ip pool print detail

Define un rango de direcciones IP reservado para repartir a los clientes. El servidor DHCP tomara direcciones de este pool, nunca fuera de el. Muestra los pools creados y cuantas direcciones libres tiene cada uno. Si el pool aparece vacio o con rango incorrecto, revisa el paso anterior.

Qué hacer

  1. Reserva la IP del router (192.168.88.1) fuera del rango del pool.
  2. Usa 192.168.88.10-192.168.88.254 como ejemplo, o adáptalo al tamaño real de tu red.
  3. Verifica con /ip pool print que el rango no se solape con IPs estáticas ya asignadas manualmente (impresoras, cámaras, servidores).
Punto de control

Un pool que se solapa con una IP estática existente puede entregar por DHCP una dirección que ya está en uso, causando conflictos intermitentes difíciles de diagnosticar después.

Interpretación

Pool creado sin solapamientos → continúa al paso 4. Rango solapado con IPs estáticas → ajústalo antes de crear el servidor DHCP.

04

4. Crear servidor DHCP

Asocia el servidor al bridge y al pool.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Crear DHCP Server · COMANDO PRINCIPAL
/ip dhcp-server network add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=192.168.88.1
/ip dhcp-server add name=dhcp1 interface=bridge1 address-pool=dhcp_pool0 disabled=no
CONSULTA · VERIFICACIÓN
/ip dhcp-server print detail
/ip dhcp-server network print detail

Define los parametros que el DHCP entregara a los clientes de esa subred -gateway y DNS-, independientemente del servicio DHCP en si. Es la "tarjeta de datos" que acompaña a cada IP entregada. Confirma que el servidor DHCP existe y esta habilitado. Si aparece "disabled=yes", el servicio esta creado pero apagado y no repartira direcciones.

Qué hacer

  1. Crea el DHCP server asociándolo al bridge y al pool creados en los pasos anteriores.
  2. Define gateway y DNS en la red DHCP para que los clientes reciban ambos datos junto con su IP.
  3. Verifica en la consulta que quede "disabled=no": un servidor creado con "disabled=yes" no reparte direcciones aunque el resto esté bien configurado.
Punto de control

Confirma que la interfaz asociada sea la correcta (el bridge, no una interfaz física individual si usas bridge): un DHCP server sobre la interfaz equivocada nunca verá las solicitudes de los clientes.

Interpretación

Servidor habilitado sobre la interfaz correcta → continúa al paso 5. Aparece deshabilitado o sobre la interfaz equivocada → corrígelo antes de validar con un cliente.

05

5. Validar

Confirma IP, gateway, DNS e Internet desde el cliente.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Validar leases · COMANDO PRINCIPAL
/ip dhcp-server lease print detail
CONSULTA · VERIFICACIÓN
/ip dhcp-server lease print detail

Lista las direcciones IP actualmente entregadas a clientes (leases). Si el equipo del cliente aparece con estado "bound", el DHCP esta funcionando de punta a punta.

Qué hacer

  1. Renueva la concesión desde el cliente (ipconfig /release seguido de /renew en Windows, o desconectar/reconectar la interfaz de red).
  2. Comprueba que la IP recibida esté dentro del rango del pool y que el gateway coincida con la IP del router.
  3. Haz ping al router y luego a una IP pública para confirmar conectividad de punta a punta.
Punto de control

Un cliente con estado "bound" en /ip dhcp-server lease print confirma que el DHCP funciona; una IP tipo 169.254.x.x (APIPA) en el cliente significa que nunca recibió respuesta del servidor.

Interpretación

Cliente con IP del pool y "bound" → configuración exitosa. Cliente sin IP o con 169.254.x.x → revisa que el enlace llegue al bridge correcto y que el DHCP server esté habilitado en esa interfaz.

Diagnóstico final

Resultado: si todas las pruebas externas son correctas y el fallo permanece, ya tienes una hipótesis más concreta. No cambies chips, puertos o placas por intuición: documenta síntomas y mediciones.

Fuentes y notas

Los comandos son un ejemplo educativo para RouterOS v7. La documentación oficial indica que DHCP requiere pool, red DHCP, dirección del gateway y servidor asociado a la interfaz. Verifica nombres de interfaces y subred antes de aplicar.
