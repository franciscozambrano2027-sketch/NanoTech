Cómo usar los comandos: primero ejecuta las consultas de diagnóstico; después aplica la configuración; finalmente vuelve a consultar para confirmar el cambio. Los valores de ejemplo deben adaptarse a tu interfaz WAN/LAN y subred.

Introducción

Objetivo

Ejemplo RouterOS v7 para una LAN 192.168.88.0/24, con gateway 192.168.88.1 y pool de clientes. La guía busca que puedas separar causas antes de sustituir componentes.

Antes de empezar: seguridad

⚠ Precaución

Desconecta el equipo cuando corresponda y no realices mediciones peligrosas sin formación e instrumental. En baterías, fuentes y placas, detén el procedimiento si detectas daño físico, líquido, olor extraño o calor anormal.

  • Documenta el estado inicial.
  • Haz una sola modificación cada vez.
  • Conserva tornillos, cables y configuración original.

1. Hacer respaldo

Antes de configurar, guarda export y backup.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.

2. Crear IP de la LAN

El gateway debe tener una IP en la interfaz LAN/bridge.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Configurar gateway LAN · COMANDO PRINCIPAL
/ip address add address=192.168.88.1/24 interface=bridge1 comment="LAN gateway"
CONSULTA · VERIFICACIÓN
/ip address print detail

Ejecuta primero la consulta cuando sea una etapa de diagnóstico. Si modificas la configuración, vuelve a ejecutar la consulta y compara el resultado. Adapta interfaces, subredes, listas WAN/LAN y nombres a tu topología.

03

3. Crear pool

El pool define las direcciones que DHCP entregará.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Crear pool de clientes · COMANDO PRINCIPAL
/ip pool add name=dhcp_pool0 ranges=192.168.88.10-192.168.88.254
CONSULTA · VERIFICACIÓN
/ip pool print detail

Ejecuta primero la consulta cuando sea una etapa de diagnóstico. Si modificas la configuración, vuelve a ejecutar la consulta y compara el resultado. Adapta interfaces, subredes, listas WAN/LAN y nombres a tu topología.

Qué hacer

  1. Reserva la IP del router fuera del pool.
  2. Usa 192.168.88.10-192.168.88.254 como ejemplo.
  3. Adapta el rango a tu red.
Punto de control

Registra el resultado antes de continuar.

Interpretación

El pool define las direcciones que DHCP entregará.

04

4. Crear servidor DHCP

Asocia el servidor al bridge y al pool.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Crear DHCP Server · COMANDO PRINCIPAL
/ip dhcp-server network add address=192.168.88.0/24 gateway=192.168.88.1 dns-server=192.168.88.1
/ip dhcp-server add name=dhcp1 interface=bridge1 address-pool=dhcp_pool0 disabled=no
CONSULTA · VERIFICACIÓN
/ip dhcp-server print detail
/ip dhcp-server network print detail

Ejecuta primero la consulta cuando sea una etapa de diagnóstico. Si modificas la configuración, vuelve a ejecutar la consulta y compara el resultado. Adapta interfaces, subredes, listas WAN/LAN y nombres a tu topología.

Qué hacer

  1. Crea el DHCP server.
  2. Define gateway y DNS en la red DHCP.
  3. Comprueba una lease desde un cliente.
Punto de control

Registra el resultado antes de continuar.

Interpretación

Asocia el servidor al bridge y al pool.

05

5. Validar

Confirma IP, gateway, DNS e Internet desde el cliente.

Orden recomendado: consulta → interpreta → configura → vuelve a consultar → prueba. Si el resultado no coincide, detén el procedimiento y corrige la hipótesis.
Validar leases · COMANDO PRINCIPAL
/ip dhcp-server lease print detail
CONSULTA · VERIFICACIÓN

Qué hacer

  1. Renueva la concesión.
  2. Comprueba IP y gateway.
  3. Haz ping al router y luego a Internet.
Punto de control

Registra el resultado antes de continuar.

Interpretación

Confirma IP, gateway, DNS e Internet desde el cliente.

Diagnóstico final

Resultado: si todas las pruebas externas son correctas y el fallo permanece, ya tienes una hipótesis más concreta. No cambies chips, puertos o placas por intuición: documenta síntomas y mediciones.

Fuentes y notas

Los comandos son un ejemplo educativo para RouterOS v7. La documentación oficial indica que DHCP requiere pool, red DHCP, dirección del gateway y servidor asociado a la interfaz. Verifica nombres de interfaces y subred antes de aplicar.
